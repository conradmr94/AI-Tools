# Spec: ship skill

- Status: Approved 2026-10-28
- Task: None. This repo has no sprints; the stage comes from the SDLC plan agreed in chat on 2026-10-28.
- Branch: `ship-skill`

## Goal

A new `ship` skill takes a finished feature branch to an open pull request: it checks the work is ready, writes the PR description from the spec and the commits, pushes the branch and opens the PR. It never merges, force-pushes or pushes the default branch, and when the work is not ready it says why and stops.

## Scope

- Touches:
  - `plugins/ship/skills/ship/SKILL.md` — new: the skill.
  - `plugins/ship/evals/` — new: eval cases, graders and the fixture-repo builder.
  - `plugins/ship/.claude-plugin/plugin.json`, `plugins/ship/.codex-plugin/plugin.json`, `.claude-plugin/marketplace.json`, `.agents/plugins/marketplace.json`, `.claude/skills/ship` (symlink) — register the plugin for Claude Code and Codex.
  - `README.md` — skill table and install lines.
- Does not touch: the `spec`, `sprints`, `explain-diff` and `explain-repo` skills. ship reads spec files and sprint logs as they are. It does not edit sprint files: recording the PR in the sprint stays with the sprints skill.

## Interfaces

Invocation, in words ("ship this", "open a PR") or as `/ship`. It always works on the current branch.

What it does, in order, stopping at the first failed check:

1. **Ready checks** — on a branch other than the default; no uncommitted or untracked changes; the matching spec (if any) has every slice ticked; the spec's `Run:` command passes; the project's documented test command passes (from `CLAUDE.md`, `AGENTS.md`, `README.md` or a `test` script, never guessed); the local branch is not behind its remote.
2. **PR text** — a title and a body (sections below), following the user's commit and PR rules in their agent instruction files.
3. **Push** — `git push -u origin <branch>`. Never `--force` or `--force-with-lease`, never the default branch.
4. **Open** — `gh pr create --base <default branch>`, or, if the branch already has an open PR, `gh pr edit` to replace its body. If `gh` cannot open it, the reply gives the title and body ready to paste.
5. **Report** — the PR link, what the checks ran and their results, and anything left for the user (manual checks from the spec's "Not covered"). It does not wait for or poll CI.

PR body sections, in this order, each left out when empty:

- **What** — what the change does, from the spec's Goal or the commits.
- **Why** — the reason, from the spec, task or commits.
- **Tests** — every spec test id with its result, the commands run, and what is not covered by automated tests.
- **Deviations** — the spec's Deviations section, condensed, plus changed files outside its `Touches:`.
- **Commits** — one line per commit saying what it changed and why; or, for a sprint task, a link to its sprint log entries instead.
- **Merging** — other open PRs that change the same files, so the user knows to expect a conflict.

## Behavior and proof

These are evals for `claude plugin eval`, written first and committed before the skill. Each case runs in a fixture repo built by one shared script: a small Python module, a README naming its test command, an `origin` that is a local bare repository (never GitHub, so no real PR can be opened), and a feature branch `rate-limit` with an approved spec whose slices are all ticked. Variants make a spec test fail, put the work on `main`, leave uncommitted changes, or drop the spec. Run, with `$OUT` a scratch directory outside the repo: `claude plugin eval plugins/ship --scaffold --runs 1 --judge-model sonnet --ablation none --no-publish --trust-plugin --allow-tools Bash Write Edit --output-dir $OUT --report $OUT/report.html`.

- **T1** Given a ready branch, when the user says "ship this", then the agent runs the spec's test command and runs `git push` for the branch without any force flag; if the push succeeds it runs `gh pr create` with `--base main`, and if the push is rejected it stops without forcing and gives the title and body ready to paste. `evals/ready`.
- **T2** Given a ready branch, when shipped, then the PR body (in the `gh` call, or pasted in the reply when `gh` fails) has *What*, *Tests* listing each spec test id with its result, *Deviations* with the spec's recorded deviation, and *Commits* with one line per commit; and it has no AI attribution line. `evals/body`.
- **T3** Given a branch where a spec test fails, when shipped, then the agent runs no `git push` and no `gh pr create`, and the reply names the failing test. `evals/red-tests`.
- **T4** Given finished work committed on `main`, when shipped, then the agent runs no `git push`, and the reply says ship needs a feature branch and offers to create one. `evals/on-main`.
- **T5** Given a ready branch plus an uncommitted change, when shipped, then the agent runs no `git commit`, `git add`, `git stash` or `git push`, and the reply names the uncommitted file and asks what to do with it. `evals/dirty`.
- **T6** Given a ready branch with no spec, when shipped, then the PR body's *Tests* section names the README's test command and its result, and *What* and *Commits* come from the commit history. `evals/no-spec`.
- **T7** Given a ready branch, when shipped, then the agent never runs `gh pr merge`, `git merge`, a force push, or a push to `main`. `evals/guards`.
- **T8** Given a ready branch, when the user says "open a pull request for this branch" without naming the skill, then the ship skill is invoked. `evals/trigger`.

Not covered by automated tests:

- Opening a real PR, updating an existing PR's body, and the *Merging* overlap check all need GitHub. Checked by hand once: ship this branch itself with the skill, and check the PR it opens.
- Codex. Checked by hand after merge with `codex plugin marketplace upgrade` and `codex plugin add ship@ai-tools`.

## Deviations

- **T7 passes against the stub.** A skill that does nothing never merges or force-pushes, so this case can't fail first. Proposed: keep it as a regression guard that must stay green. The "must not push or open a PR" checks inside T3, T4 and T5 also pass against the stub, but each of those cases still fails on its reply check. Kept as a guard; approved by Owner 2026-10-28 in chat.
- **T1's PR check made conditional on the push.** The eval sandbox blocks the git helper that a push starts, so the fixture's push fails in some runs regardless of the skill, and the skill then correctly stops before `gh`. The check now requires `gh pr create --base main` when the push succeeded, and, when it was rejected, a stop with no force and the title and body ready to paste. T1's sentence now reads as below; its test-run and no-force push checks are unchanged. Opening a real PR is proven by the manual check. Approved by Owner 2026-10-29 in chat.
- **Paste-ready text after any failed push or `gh`.** The report now includes the title and body whenever the push or `gh` fails, not only when `gh` fails, so the write-up is never lost. Added with the T1 change; approved by Owner 2026-10-29 in chat.
- **Fixture `origin` helpers wrapped.** `origin`'s receive and upload helpers run through small wrappers that use git's own exec path, that git first on `PATH`, and a temp folder inside the repo, because the eval sandbox blocks the `/usr/bin` git shim and the system temp folder. Changes nothing approved.
- **T2 and T6 judges read the whole run.** Their graders use `focus: trace`, so the judge sees the `gh` call or the pasted body wherever it appears, not only the final reply. The runner rejects the `target:` key on LLM graders. Changes nothing approved.
